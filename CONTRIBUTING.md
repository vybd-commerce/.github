# Contributing to Vybd

Thanks for helping. These guidelines apply to every public repository in this organisation unless a repository has its own `CONTRIBUTING.md`.

## Before you start

- **Bugs and small fixes:** open an issue or go straight to a pull request.
- **New features or larger changes:** open an issue first and describe the problem you want to solve. This saves you from building something we cannot merge.
- **Security problems:** do not open an issue. Follow [SECURITY.md](SECURITY.md).

## Pull requests

1. Fork the repository and create a branch from the default branch.
2. Keep the change focused. One problem per pull request.
3. Add or update tests for behaviour you change, and run the repository's checks (see its README).
4. Describe what the change does and why, and link the issue it closes.
5. Never commit secrets, API keys, or customer or supplier data.

## Licence and sign-off

Unless a repository says otherwise, code is licensed under [Apache-2.0](LICENSE). By contributing you agree that your contribution is licensed under the same terms.

Sign your commits to certify the [Developer Certificate of Origin](https://developercertificate.org/):

```
git commit -s -m "Describe the change"
```

## Names and logos

The licence covers the code. It does not grant rights to the Vybd name or logo.

## Conduct

Everyone taking part is expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
